How the fused softmax kernels use the GPU

The launch is grid = rows, block = threads: block b owns row b, and thread t walks that row with a stride of blockDim.x. Then the warps reduce with shuffles, and the block reduces through shared memory. Use the toy controls to watch one row, then try real sizes in the occupancy calculator at the bottom.

1. Grid: one block per row

A score matrix with rows launches blocks. Click a block to pick its row.

2. Block: threads walk the row with a stride

Each color is one warp (32 threads). In iteration k, thread t reads element t + k·blockDim.x. Neighbouring lanes read neighbouring addresses, so each warp load is one coalesced 64-byte request.

3. Warp reduction with __shfl_xor_sync

Every lane holds its partial result. At each step, lane i swaps with lane i ^ offset and keeps the combined value. After 5 steps (offsets 16, 8, 4, 2, 1), all 32 lanes hold the same result, with no shared memory and no __syncthreads.

Across warps: lane 0 of each warp writes its result to smem[warp], then __syncthreads(), then every warp reads smem[lane] for lane < warps and runs the same 5-step shuffle again. Every thread ends with the block result, so the early return for an all -inf row is taken by the whole block together.

4. DRAM passes per kernel

The same row, read by the three kernels. The idealized traffic counts 2 bytes per access and assumes no L2 hits.
