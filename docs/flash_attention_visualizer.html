How FlashAttention uses online softmax

FlashAttention computes O = softmax(QKᵀ / √d) V without writing the N × N score matrix to HBM. It streams K and V tiles through on-chip memory and keeps a running max m, a running sum l and an unnormalized output O per query row. This is the same (m, d) rule as kernel B2 in this repo, applied per tile and fused with the matmuls.

1. What lives in HBM, and what this repo measures

Orange boxes are N × N tensors written to or read from HBM (DRAM). Green boxes stay in registers or shared memory.

Standard attention (5+ kernels)
Q, K→S = QKᵀ (N×N)→P = softmax(S) (N×N)→P·V→O (N×d)
This repo (softmax only, S already in HBM)
Q, K→S (N×N), read 1 to 3 times→one fused kernel: B1, B2 or B3→P (N×N), written once→P·V
FlashAttention (1 kernel)
Q tile+K, V tiles→S tile, P tile, running m, l, O in SRAM→O (N×d) and logsumexp (N)
N × N tensor in HBMon chip
The kernels here remove passes over S, but S and P still cross DRAM. Their memory stays O(N²) (2,048 MiB above the input at N = 32,768). FlashAttention's O(N) memory comes from never creating S and P, which this lab does not attempt.
